# 时迹 · 极简使用时长与限额

一个只有 **81 KB** 的 Android 本地应用：统计屏幕使用 + **息屏/后台音频播放**，生成日 / 周 / 月回顾，达到每日额度后接管屏幕并阻止再次打开，还可以接入 DeepSeek（或 OpenAI 兼容）接口，按你设定的风格生成评价。提供浅色 / 深色 / 跟随系统三种外观。

- 包名：`com.shiji.guard`
- 版本：1.3（versionCode 4）
- 最低系统：Android 9（API 28），已在 Android 16 / HyperOS 真机验证
- 下载：[GitHub Releases](https://github.com/yuyu623/shiji-guard/releases/latest)
- 源码：`https://github.com/yuyu623/shiji-guard`

## 一、安装

### 直接下载
从 [Releases](https://github.com/yuyu623/shiji-guard/releases/latest) 下载 `ShiJi-v1.3.apk`，安装即可。

### 或 adb 安装

```powershell
adb install --no-streaming -r -d ShiJi-v1.3.apk
```

### 首次授权

```powershell
powershell -ExecutionPolicy Bypass -File tools\setup.ps1
```

`setup.ps1` 会依次开启：使用情况访问、悬浮窗 / 后台启动、通知、无障碍、媒体会话（通知使用权）、电池白名单。

> 手机重启、系统更新或重装应用后，无障碍可能被系统重置。重新运行一次 `tools\setup.ps1` 即可恢复全部授权。

## 二、四个页面

### 今日
- **总占用 = 屏幕使用 + 后台音频**（自动排除桌面、系统 UI 和「时迹」自身，避免虚增）
- 「屏幕 3h37m · 后台音频 2m」拆分
- 与昨日对比
- 24 小时使用条：能直接看到一天里哪些时段在用手机
- 使用最多的应用（前 6 个，含屏幕/后台拆分与限额进度）
- AI 点评卡片：按当前风格生成，可「换一个」重写
- 达到限额被拦截的次数

### 回顾
- 「本周 / 本月」切换
- 周期总占用、屏幕/后台拆分、与上一周期对比
- 每日柱状图（今天高亮，含后台音频）
- 应用排行与「含后台」标记
- AI 周评 / 月评

### 限制
- 每个应用一条规则：图标、今日已用、每日额度、开关、进度
- 点整行可修改额度或移除规则；右侧开关只暂停拦截，统计继续
- 「＋ 添加应用」：按使用时长排序的可搜索应用列表
- 额度选项：不限 / 1 / 5 / 15 / 30 / 45 / 60 / 90 / 120 分钟

### 设置
- 外观：跟随系统 / 浅色 / 深色
- AI 评价：风格、强度 7 档、关注点、长度、自定义描述
- 五项权限的实时状态与跳转（含「媒体会话（后台音频）」）
- AI 接口配置：接口地址、模型、API Key、保存、测试连接、恢复默认
- 持续记录开关、记录服务状态与重启
- 直达 HyperOS 自启动设置
- 清空 AI 点评 / 拦截记录 / 使用记录
- 关于与隐私说明

### 主题
- 三档可选：**跟随系统**（默认）、**浅色**、**深色**
- 深色：原来的黑底 + 青柠强调色；浅色：暖白纸感底 + 橄榄绿强调色，状态栏图标也会跟着切换深/浅
- 跟随系统时，手机切换深色模式，应用会自动重建界面并保留当前标签页
- 主题只改变配色，不影响统计口径、限额和拦截；拦截页也会使用当前主题
- 选择会持久化，下次启动保持不变

## 三、限额与拦截的真实行为

达到每日额度后，时迹会：

1. 在当前应用上方显示全屏拦截页（显示应用名、已用 / 额度、次日 00:00 重置）
2. 自动回到桌面
3. 尝试结束该应用的后台进程
4. 如果它正在后台播放音频，用 `MediaController` 暂停播放
5. 你再次点开该应用时，会在 1～2 秒内再次被拦截，直到第二天零点

额度是**屏幕 + 后台音频**的合计，所以“只听歌不看屏”也会消耗额度。

**需要说明的系统限制**：Android 不允许普通应用真正「强制停止」另一个应用（`am force-stop` 需要 root / shell）。时迹用的是无障碍全屏覆盖 + 返回桌面 + `killBackgroundProcesses`，效果是「无法继续使用」，而不是把进程从系统里彻底杀掉。这也是所有同类免 root 应用的做法。

拦截页在 12 秒后会自动消失（避免卡住桌面），但应用仍处于超限状态，重新打开会再次拦截。

## 四、后台音频统计

### 能做到什么
- 通过通知使用权读取 `MediaSession`，知道哪个 App 在放音频、是否在播放
- 只要媒体会话是 `PLAYING`，且屏幕关闭或该 App 不在前台，就按秒累计为「后台音频」
- 前台且亮屏时播放**不重复计入后台**；那段时间已经算在屏幕使用里
- 后台音频计入总占用、应用排行、每日限额和 AI 简报

### 需要开启
设置 → 权限 → **媒体会话（后台音频）** → 去开启，允许「时迹 · 后台音频」。

或 adb：

```powershell
adb shell cmd notification allow_listener com.shiji.guard/com.shiji.guard.MediaListenerService
```

这个权限是 Android 的“通知使用权”，系统会把它理解为可读取通知的权限；时迹的代码只读取媒体会话，不读取通知内容。

### 边界
- 只能识别**媒体/音频播放**，不能识别微信同步、下载、定位、后台刷新等通用后台运行；Android 没有公开 API
- 极少数不放 MediaSession 的播放器可能漏记
- 到额度暂停播放是通过 `MediaController` 发的，个别 App 可能不响应；不响应时会每 4 秒重试
- 后台音频活跃时会持有 partial wake lock，保证息屏也能计时；停止播放后自动释放

## 五、接入 AI 接口

### 1. 填 Key
设置 → AI 接口：

- 接口地址：`https://api.deepseek.com`（默认，已填好）
- 模型：`deepseek-chat`（默认，已填好）
- API Key：填你在 DeepSeek 开放平台创建的 Key
- 点「保存配置」→「测试连接」

也支持任何 OpenAI 兼容的 `/chat/completions` 接口，例如自建网关：
- 地址填 `https://your-host/v1`，应用会自动拼成 `/v1/chat/completions`
- 模型填你的模型名

### 2. 评价风格
设置 → AI 评价，全局一套，日 / 周 / 月都使用当前风格：

- **风格**：直白批评（默认）、温柔陪伴、冷静分析、幽默反讽、教练模式、自定义
- **强度**：1～7 档，默认 4/7「直接」；7/7 是「很严厉」，可以尖锐，但仍只批评行为
- **关注点**：时间结构 / 熬夜 / 拖延 / 单应用 / 行动建议，可多选；默认时间结构 + 行动建议
- **长度**：一句话 / 短评 / 详细，默认短评
- **自定义**：最多 160 字，选择「自定义」时生效；为空时不会自动生成

「幽默反讽」会使用反讽、夸张、网络用语和热梗，但 prompt 明确要求梗要自然、不堆砌、不用过时或冒犯性的梗；所有风格都禁止人身攻击、羞辱、歧视和医疗/心理诊断。

风格、强度、关注点、长度都会进入 system prompt。下面是实际生成的一段 humor / 7 档 / 时间结构 + 熬夜 + 行动建议 / 详细的 prompt 片段：

```text
【风格】幽默反讽
像一个损友，用反讽、夸张、网络用语和热梗吐槽，但只吐槽行为，不否定整个人。
梗要自然，不要堆砌，不要用过时或冒犯性的梗。

【强度】7/7
很严厉：非常直接、强烈不满，可以尖锐，但绝不侮辱人格、不攻击外貌或身份。

【关注点】
- 时间结构：关注使用时段、碎片化程度、连续使用长度。
- 熬夜：关注睡前和凌晨的使用，以及它对睡眠的挤占。
- 行动建议：最后落到一个具体、当天能做的动作。

【长度】4 到 6 句，180 字以内，可以有更完整的观察和建议。
```

### 3. 生成与自动重写
- 今日页 / 回顾页的 AI 卡片点「生成」
- 已有评价时点「换一个」会以不同角度重写
- **只要改了风格、强度、关注点、长度或自定义描述，本机 AI 点评缓存会立即清空；24 小时内打开对应的日 / 周 / 月点评，会自动按新风格重写，不用再点按钮**
- 自动重写需要已填写 API Key；没有 Key 时不会发请求
- 每张卡片头部会显示当前风格，例如「直白批评 · 4/7」
- 生成结果按「日 / 周 / 月 + 风格签名」缓存在本机；换回旧风格不会命中旧缓存（旧缓存已被清空）
- 设置里可以「清空 AI 点评」后重新生成

### 4. 数据说明
生成点评时，发送的是**汇总后的时长数据**（总时长、每日分布、应用排名、限额规则、拦截次数）+ 当前风格描述，不包含屏幕内容、聊天记录或任何文件。Key 只保存在本机 SharedPreferences 里。

不填 Key 也可以用全部统计和限额功能，只是 AI 卡片会提示未配置，切换风格也不会触发请求。

## 六、总结是怎么算的

- 屏幕数据：系统 `UsageStatsManager` 的前台 / 亮灭屏事件，还原成一段段「应用在前台」的会话
- 后台音频：`MediaSession` 处于 `PLAYING`，且屏幕关闭或 App 不在前台时，按秒累计
- 前台且亮屏的播放不重复计入后台，已经算在屏幕使用里
- 总占用 = 屏幕会话 + 后台音频会话；两者都会按本地零点切分，不会串天
- 首次启动会回填最近 7 天的系统事件，装好当天就有周数据
- 日：当天 0 点到现在；周：本周一到现在；月：本月 1 号到现在
- 桌面、`com.android.systemui`、时迹自身不计入总时长和应用排行
- 数据保留 400 天，之后自动清理
- 后台音频会话期间持有 partial wake lock，停止播放后释放；这是息屏也能计时、同时不过度耗电的关键

## 七、后台保活（HyperOS 必看）

时迹同时用了四层保活：

1. 前台服务 + 常驻通知（`specialUse` 类型）
2. 无障碍服务绑定
3. 一个 1 像素、不可触摸的常驻窗口，避免 HyperOS 把完全不可见的进程冻结（这是实测有效的关键）
4. 后台音频播放期间持有 partial wake lock，保证息屏也能计时；暂停/停止后自动释放

建议再手动做两件事（设置里「自启动 / 后台运行」可以直接跳转）：

1. 应用信息 → 省电策略 → **无限制**
2. 允许 **自启动**；最近任务里给时迹加锁

如果桌面上的「记录中」变成「未在记录」，或「限制」页顶部显示无障碍未开启，或首页出现「后台音频统计未开启」：

```powershell
powershell -ExecutionPolicy Bypass -File tools\setup.ps1
```

`setup.ps1` 会同时恢复使用情况、无障碍、通知、媒体会话（通知使用权）和电池白名单。

## 八、重新构建 / 安装

不依赖 Gradle / AndroidX，直接用 SDK 的 aapt2 + javac + d8 + apksigner。

需要：

- Android SDK Platform 36、Build-Tools 36.1.0
- JDK 17+（脚本按 Java 11 字节码编译）
- 一个本地签名 keystore；密码通过环境变量传入，**不要提交到仓库**

```powershell
$env:ANDROID_HOME = 'C:\path\to\Android\Sdk'
$env:JAVA_HOME = 'C:\path\to\jdk'
$env:SHIJI_KS_PASS = 'your-keystore-password'

powershell -ExecutionPolicy Bypass -File tools\build.ps1            # 只打包
powershell -ExecutionPolicy Bypass -File tools\build.ps1 -Install   # 打包 + 安装 + 授权
```

首次构建时如果没有 `keystore.jks`，脚本会自动生成；升级时必须保留同一个 keystore，否则不能覆盖安装。产物在 `dist/`，已被 `.gitignore` 忽略。

安装使用 `adb install --no-streaming`，兼容 MIUI 的 USB 安装限制。

## 九、已知限制

1. 无法真正 force-stop 其他应用（见第三节），拦截效果依靠无障碍覆盖 + 回桌面。
2. 后台音频只能识别带 `MediaSession` 的播放器；微信同步、下载、定位等通用后台运行没有公开 API，无法统计。
3. 后台暂停播放依赖各 App 对 `MediaController.pause()` 的响应，个别播放器可能暂停失败，会每 4 秒重试。
4. 未开启「媒体会话」权限时，后台音频不统计；首页会出现「后台音频统计未开启」提示。
5. 部分系统应用（设置、权限弹窗）不要设限额，可能影响系统操作。
6. 无障碍服务可能被 HyperOS 在重启 / 更新后关闭，需要重新开启；应用内状态会如实显示。
7. 周 / 月数据从安装（或首次回填的 7 天）开始积累，之前的日期会是空的。
8. 跨零点时，正在使用的应用会从零点重新计时。
9. AI 需要网络和有效 Key；错误会直接显示在卡片上（如 HTTP 401）。
10. 评价风格是通过 prompt 实现的，不同模型（或同一模型不同温度）对“直白/幽默”的执行会有差异；强度 7/7 仍禁止人身攻击和医疗诊断。
11. 风格切换后的自动重写窗口是 24 小时；超过后需要手动点「生成」。自动重写只针对你实际打开的那个周期，不会一次生成三份。
12. 自定义风格为空时不会自动生成，手动点「生成」也会提示补充。
13. 这是自签名 APK，不通过应用商店，系统可能提示「未知来源」，属正常。
